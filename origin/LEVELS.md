# Bumpy: формат уровней оригинала

Разбор `origin/Bumpy.tap (1)/BUMPY.TAP` (ZX Spectrum, Bumpy, Loriciels 1989).
Цель — вытащить метаданные 100 уровней для переиспользования.

## Лента (TAP)

`BUMPY.TAP` — обычный TAP из четырёх блоков:

| Блок  | Имя         | Тип     | Загрузка           | Длина |
|-------|-------------|---------|--------------------|-------|
| BASIC | `BUMPY`     | Program | автозапуск стр. 10 | 191   |
| экран | `BUMPY.SCR` | Bytes   | 32768              | 6912  |
| код   | `BUMPY.CDE` | Code    | 25000 (0x61A8)     | 38700 |

BASIC сводится к:

```
10 POKE 23624,0 : POKE 23693,0 : POKE 23607,128
   CLEAR 24999 : LOAD "" SCREEN$ : LOAD "" CODE 25000
   POKE 23607,60 : POKE 23685,0 : RANDOMIZE USR 43900
```

Точка входа `43900`. В коде (плюс экран загрузки, который код перезатирает)
и лежат данные уровней.

## Таблица уровней

Загрузчик уровня находится в районе `53097` (дизассемблер SkoolKit):

```
53110 LD A,(43776)     ; индекс текущего уровня, 0..99
53113 LD B,A
53114 INC B
53115 LD DE,75         ; шаг записи
53118 LD HL,35825      ; база таблицы
53121 ADD HL,DE        ; HL = 35825 + 75*(level+1)  (выполняется level+1 раз)
53128 LD A,(HL+36) ; -> 43802   ; стартовая ячейка шара
53140 LDIR 75 -> 43552          ; копия записи в рабочую область
```

Отсюда:

* **адрес таблицы `35825`** (0x8BF1), **шаг 75 байт**;
* запись уровня с индексом `n` (0..99) лежит по `35825 + 75*(n+1)`;
  запись 0 — пустышка, записи 1..100 — уровни 1..100, дальше нули;
* индекс уровня хранится в `43776`, счёт идёт `0..99` (при `+1 == 100` → 0),
  игровой уровень = `индекс + 1`.

Проверка: запись 100 непустая, 101 и далее — нули.

## Формат записи (75 байт)

| Смещение | Размер | Значение                                              |
|----------|--------|-------------------------------------------------------|
| 0..35    | 36     | сетка 6×6, упакованная по 2 типа в байт               |
| 36       | 1      | стартовая ячейка шара (`start_cell`, 0..35)           |
| 37       | 1      | сколько объектов собрать до открытия выхода (`timer`) |
| 38       | 1      | **финишная ячейка / выход** (`timer_cell`, 0..35)     |
| 39..74   | 36     | объекты по ячейкам (`objects`)                        |

### Сетка

36 байт — это два слоя по нибблам:

* **младший ниббл** → слой `lo` (игровой/интерактивный слой),
* **старший ниббл** → слой `hi` (вертикальные перегородки/стены).

Индекс ячейки `k = row*6 + col` (шаг строки = 6). Ячейка «ниже» — `k+6`
(см. код на `51075`), т.е. разложение `divmod(k, 6)`.

### Объекты

В рабочей области объект текущей ячейки лежит по `43591 + k`, т.е. это
`record[39 + k]`. Код объекта (1..40) индексирует таблицу определений
`27824` с шагом 56 байт (обработчик `53241`).

### Выход (финишная ячейка)

Байт 37 попадает в `43589` (счётчик), байт 38 — в `43590` (**ячейка выхода**).

Байт 37 **в точности равен числу объектов с кодом `>= 5`** в уровне
(проверено на всех 100 уровнях). Каждый сбор такого объекта (`47527` →
`47687`) уменьшает счётчик `43589`; при обнулении (`47708`) вызывается
`48313`, который присваивает ячейке `43590` тип `lo = 11` — это открытый
выход.

Готово: когда шар оказывается в ячейке с `lo = 11`, уровень завершается —
`47076` сравнивает текущий тип с 11 и при совпадении (`47213`) ставит
состояние `43520 = 8`, а процедура `45762` увеличивает номер уровня.

Итого: **`timer_cell` (байт 38) — это финишная ячейка**, а `timer` (байт 37) —
сколько объектов (код `>= 5`) надо собрать, чтобы выход в ней открылся.
Иногда финиш совпадает со стартом (например, уровни 1 и 3).

### Объекты-предметы (код 1..4)

Объекты с кодом 1..4 обрабатываются отдельной таблицей `47677` и не влияют на
открытие выхода (они увеличивают счётчики `43773`/`43774`/`43775`/`43777`).

Подтверждено по геймплею: код **1** — молоток (hammer), код **3** — капля
(drop). Объекты с кодом `>= 5` идут через общий обработчик и уменьшают счётчик
выхода.

## Типы слоёв (по обработчикам отрисовки)

Слой `lo` обрабатывается таблицей переходов `50600` (13 записей, типы 0..12),
слой `hi` — таблицей `50626` (5 записей, типы 0..4).

`lo` (проверено по обработчикам у 53412 и далее):

| Тип | Отрисовка (адрес данных тайла)                    | Примечание                                                                 |
|-----|---------------------------------------------------|----------------------------------------------------------------------------|
| 0   | —                                                 | пусто                                                                      |
| 1   | DE=30600                                          |                                                                            |
| 2   | DE=30976                                          | **сжимающаяся (shrinkable) платформа** — подтверждено по геймплею           |
| 3   | DE=31352 (+1 px)                                  |                                                                            |
| 4   | DE=31586 (+2 px)                                  |                                                                            |
| 5   | DE=31714                                          |                                                                            |
| 6   | DE=30632, смещение +10160                         |                                                                            |
| 7   | DE=30712, смещение +10160                         |                                                                            |
| 8   | DE=30600 + метка в `43699` + большой спрайт 33101 | **горящая (burning) платформа** — подтверждено по геймплею                |
| 9   | DE=31714 + метка в `43699` + большой спрайт 33101 |                                                                            |
| 10  | DE=33605 ×4, счётчик попаданий `43735` = 8        | **кирпичная стена (block)** — подтверждено по геймплею                      |
| 11  | — (JP 53236)                                      | **открытый выход**; появляется в `timer_cell` после сбора `timer` объектов |
| 12  | DE=32090                                          |                                                                            |

`hi` (подтверждено по геймплею — это **вертикальные перегородки**):

| Тип | Данные тайла | Значение                                                            |
|-----|--------------|---------------------------------------------------------------------|
| 0   | — (пусто)    |                                                                       |
| 1   | DE=32636     | разрушаемая (destructible), уже **с двумя** ударами                   |
| 2   | DE=32588     | разрушаемая (destructible), уже **с одним** ударом                    |
| 3   | DE=32540     | разрушаемая (destructible), целая                                     |
| 4   | DE=32348     | неразрушаемая (indestructible)                                        |

Столбец `gc` матрицы описывает границу между вертикалями `gc` и `gc+1`,
т.е. первый столбец — перегородки между 0 и 1 вертикалью игровых ячеек.
Последний столбец (`gc = 5`) в данных всегда пуст (проверено на всех 100
уровнях) и не используется.

Дополнительно: обработчик `48506` использует `43804` (текущий тип `lo`);
типы 1..5 извлекают 24-байтовое описание из таблицы `50474`. Это наводит на
мысль, что `lo` 1..5 — варианты «платформы/направления», а 6..12 — особые
тайлы. Точные игровые имена (наклонная / липкая / шипы / горящая и т.п.)
нужно подтверждать по геймплею: обработчик `lo=10` имеет счётчик в 8 попаданий,
`lo=11` появляется по таймеру.

## Темы (7, циклически)

Уровень → `(index mod 7) + 1` (код `53040`). На тему берётся 3 байта из
таблицы `57625` с шагом 3 (похоже на INK/PAPER/BORDER):

| Тема | Байты |
|------|-------|
| 1 | 03 0F 19 |
| 2 | 01 0E 14 |
| 3 | 0C 18 1A |
| 4 | 03 06 1A |
| 5 | 04 11 1A |
| 6 | 09 12 1A |
| 7 | 03 10 1A |

## Извлечение

```
python3 tools/extract_levels.py            # -> main/levels.json
python3 tools/extract_levels.py --text     # человекочитаемый дамп
```

`levels.json` содержит по уровням: `grid_lo`, `grid_hi`, `objects` (сетки
6×6), `start_cell`, `timer`, `timer_cell`, `theme`, `raw_grid` (36 байт как
есть), плюс гистограммы типов и таблицу тем.

## Наблюдаемые распределения типов (100 уровней)

* `lo`: 0 — 1419, 1 — 390, 2 — 263, 3 — 169, 4 — 486, 5 — 93, 6 — 158,
  7 — 160, 8 — 40, 9 — 30, 10 — 144, 12 — 248 (11/13/14/15 в данных не
  встречаются).
* `hi`: 0 — 2885, 1 — 153, 2 — 46, 3 — 190, 4 — 326.
* `objects`: 0 — 2592, далее коды 1..40.

## Оговорки

* Игровые названия части типов `lo` (и все типы `hi`) подтверждены по
  геймплею, остальные — только по поведению обработчиков и адресам тайлов.
* Адреса тайлов (`DE=...`) — это исходные указатели отрисовщика (`58350`),
  а не готовые 8×8 битмапы; формат тайловой графики не разбирался.
